# QQ 接入指南

工作台不绑定任何 QQ 框架：它只依赖 **OneBot 11 HTTP 协议**，通过 `get_login_info` / `get_group_list` / `get_group_msg_history` 三个接口**读取**群消息，通过 `send_private_msg` / `send_group_msg` 把日报**私聊发给你的主号**。可选的实时上报走 `POST /api/ingest/onebot`。

所以你需要自己准备一个 OneBot 11 服务端（下文统称「OneBot 服务端」）。本项目约定的地址是 `http://127.0.0.1:3010`，端口可以在工作台里改。

## 一、先想清楚：用小号

所有这类工具都是非官方客户端，**存在被腾讯风控（限制登录、冻结）的可能**。

1. 准备一个「情报员小号」，只用来登录 OneBot 服务端。
2. 用小号加入你想监控的群。
3. 主号**不要**登录它。主号想收日报，就让小号私聊主号（见第六步）。
4. 不要让小号做自动加群、自动回复、频繁发消息这类事。工作台只读消息，推送也只发给你自己。

## 二、选一个 OneBot 11 实现

| 实现 | 平台 | 许可 | 说明 |
|---|---|---|---|
| [SnowLuma](https://github.com/TomyJan/SnowLuma) | Windows x64、Linux x64 / arm64 | 源码可见的**非商业**许可（不是 OSI 开源） | 需按其文档安装；Lite 版需 Node.js 24+ |
| [LuckyLilliaBot](https://github.com/LuckyLilliaDev/LuckyLilliaBot) | Windows x64、macOS arm64、Linux x64 / arm64 | **GPL-2.0** | 需 Node.js 24+ |
| 其它 OneBot 11 实现 | 视实现而定 | 视实现而定 | 只要能开 HTTP 服务端并支持上面那几个接口即可 |

**本项目不为任何实现背书，也不分发它们的二进制。** 版本、许可、可用性都可能变化，请以各自仓库的最新说明为准。

> **历史说明：** 早期版本用的是 NapCatQQ，它已停止维护（仓库内容清空、Release 与 Tag 全部下线），因此本仓库不再提供它的下载脚本。你仍可自行寻找历史副本，但那不在本项目支持范围内。

装好之后启动它，并用**小号**登录，然后进入它的 WebUI / 配置文件，做下一步的两项配置。

## 三、开启 HTTP 服务端（必做）

在你的 OneBot 实现的「网络配置」里新建一个 **HTTP 服务端（HTTP Server）**：

| 项目 | 填写 |
|---|---|
| 名称 | bureau |
| 启用 | 打开 |
| 主机 | `127.0.0.1` |
| 端口 | `3010` |
| 消息格式 | `array` |
| Token | 自己生成一个随机串（见下） |
| CORS、WebSocket | 关闭 |

**务必把主机设成 `127.0.0.1`**，不要用 `0.0.0.0`：后者会让同一局域网的设备都能访问你的 QQ。

生成随机 token：

```powershell
# Windows PowerShell
[guid]::NewGuid().ToString('N')
```

```bash
# macOS / Linux
uuidgen | tr -d '-' | tr 'A-Z' 'a-z'
```

如果实现要求直接改配置文件而不是点界面，配置结构通常是 `onebot11_<QQ号>.json`，可参考 `scripts/tools/onebot-config-template.json`。

## 四、可选：开启实时上报

不开也能用：定时任务会按时间窗口回溯历史消息。开了以后，新消息会实时推到工作台大屏。

1. 新建一个 **HTTP 客户端（HTTP Client / 上报）**：

   | 项目 | 填写 |
   |---|---|
   | 名称 | bureau-ingest |
   | 启用 | 打开 |
   | URL | `http://127.0.0.1:8765/api/ingest/onebot` |
   | 消息格式 | `array` |
   | 上报自身消息 | 关闭 |
   | Token | 与第三步**相同**的 token |

2. 保存。服务端会用这个 token 给每次上报签名（请求头 `X-Signature: sha1=…`），工作台据此校验来源。
3. 工作台只接受本机发来的上报，非白名单群的消息直接丢弃，不会保存。

## 五、在工作台里填写配置

1. 工作台 →「情报源」→ QQ，适配器选 **OneBot 11（QQ）**（这个适配器对任何 OneBot 11 服务端都适用）。
2. 填写：

   | 项目 | 填写 |
   |---|---|
   | OneBot HTTP 地址 | `http://127.0.0.1:3010` |
   | Token | 第三步的 token |
   | 上报签名密钥 | 留空（与 Token 相同时不用填） |

3. 点「测试」，看到「已连接 OneBot 11 服务端，登录账号 情报员（QQ 号）」即成功。
4. 点「刷新群列表」，把要监控的群加入白名单。

| 提示 | 原因 | 怎么办 |
|---|---|---|
| 连不上 OneBot 11 服务端 | 服务端没启动，或没建 HTTP 服务器，或端口不对 | 回到第三、四步 |
| 服务端拒绝访问：token 不正确 | 工作台和服务端的 token 不一致 | 重新复制 token |
| QQ 尚未登录 | 小号掉线 | 重新扫码登录 |
| 服务端找不到更早的消息 | 本机 QQ 只保存了这么多历史 | 正常现象；开启实时上报可避免遗漏 |

## 六、主号怎么收日报

1. 用小号加主号为好友（**必须互为好友**，否则私聊会失败）。
2. 工作台 →「推送」→ 新增通道 →「QQ（OneBot 11）」：
   - OneBot HTTP 地址、Token：与第五步相同
   - 发送到：私聊
   - QQ 号：你的**主号** QQ 号
3. 点「发送测试」，主号应收到一条「情报局通道测试」。
4. 日报会按每段不超过 1500 字发送，最多 6 段，段间隔 1.5 秒；超出部分请在工作台查看。

也可以发到群：「发送到」选群聊，填群号（小号要在群里，且没有被禁言）。

## 七、接不了 QQ 的时候

把聊天记录导出后导入即可，不需要任何框架：

- 支持 WeChatDataAnalysis / WeFlow / ChatLab 的 JSON、CSV，或直接复制粘贴文本。
- 放进 `data/inbox/qq/`（文件名随意，处理过会记到 `.processed.json`），或在「情报源」页面拖进导入区。
